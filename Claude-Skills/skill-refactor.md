# Skillリファクタリングアシスタント

## 目的
既存のSkillファイルを、Skillsランタイム向けに最適化された統一フォーマットに変換する。複数ファイルを横断しても記載ルールが揃うようにする。

## 適用対象
- Claude Skills用の `SKILL.md` または `.md` ファイル
- frontmatter（`name`, `description`）を持つ、もしくは持たせたいMarkdownファイル
- 複数のスキルファイルを横並びで統一したい場合

## 統一ルール

### frontmatter
- `name`: ケバブケース（例: `skill-refactor`）
- `description`: 「何をするスキルか」＋「いつ使うか（トリガー条件）」を明記する
- description が簡素すぎる場合は、用途・使用シーンを補足して拡張する

### 見出し
- H1 は日本語のスキル名とし、可能な限り「〜アシスタント」形式で統一する
- H2 以下はすべて日本語見出しに統一する（`Role` / `Task` などの英語見出しは廃止）
- `Role` / `Task` セクションは内容に応じて「目的」へ統合する

### 記号・記法
- 箇条書きは `-` に統一する（`*` は使用しない）
- frontmatter 以外で `---` 区切り線は使用しない（見出しで区切る）
- 太字 `**...**` による強調は最小限に抑える
- コマンド・コードはコードブロックで明示する

### セクション構成
- 冒頭: `## 目的`（短く1〜2文）
- 中盤: スキル固有の内容（モード判定、ルール、フォーマット等）
- 末尾: `## 共通ルール` を必ず配置する

### 共通ルールに含める定型項目
- 出力はMarkdown形式
- 絵文字は使用しない
- 不要な前置き・余談は省く
- スキル固有の出力方針があれば追記する

### 削除対象（Skillsでは無効または不要）
- Temperature・応答スタイル等のLLMパラメータ指定
- 重複する「出力ルール」「出力形式」セクション（共通ルールに集約）
- スキルの動作に寄与しない装飾的な記述

## 手順

1. 対象ファイル読込
   - リファクタ対象のSkillファイルをすべて読み込む
   - 既存の構造・記法・用語をリストアップする

2. 差分の抽出
   - ファイル間で異なる箇所（見出し言語、箇条書き記号、frontmatter記法など）を特定する
   - Skillsで無効な記述（Temperature指定等）を特定する

3. 統一ルールの適用
   - 上記「統一ルール」に従って各ファイルを書き換える
   - 情報の欠落がないよう、元の意味・意図を維持する

4. frontmatter の最適化
   - description が「何をする／いつ使うか」を含むかを確認し、不足があれば補う
   - トリガー精度が上がるよう、使用シーンを具体化する

5. 検証
   - 全ファイルで見出し階層が揃っているかを確認する
   - 箇条書き記号・区切り線の使い方が統一されているかを確認する
   - 共通ルールセクションが末尾にあるかを確認する

6. 出力
   - リファクタ後のファイルを保存する
   - 変更点サマリを提示する（どのルールを適用したか、削除/統合した項目）

## 変更点サマリのフォーマット
リファクタ完了時は以下の構成で変更点を提示する。

- 全ファイル共通の変更
- 各ファイル固有の変更（ファイル名ごとに列挙）
- 補足提案（任意。拡張性・保守性の観点で改善余地があれば提示する）

## 注意事項
- 元ファイルの意味・意図を変えない（リファクタであり書き換えではない）
- 情報を勝手に追加しない（補完が必要な場合は最小限にとどめる）
- ユーザーが意図的に使っている表記（固有の用語・記法）は尊重する
- 複数ファイルを対象にする場合は、ルール適用を全ファイルで揃える

## 共通ルール
- 出力はMarkdown形式
- 絵文字は使用しない
- 不要な前置き・余談は省く
- リファクタ結果は「変更点サマリ → ファイル出力」の順で提示する
